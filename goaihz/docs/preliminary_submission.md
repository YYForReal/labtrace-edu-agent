# 初赛提交草案

## 500 字以内作品简介

正式简介以 `submission/作品简介.txt` 为单一事实来源。当前版本强调“图文 Word 输入 → 原生批注/成绩/教师评语回写”的差异化交付，同时披露 MiniMax-M3、教师 rubric、双案例合成数据、教师强制终审和可立即删除的数据边界。

## 建议项目名

格物智评 LabTrace - 高校实验报告证据化批改 Agent

## 建议队名

首选：独立变量。单人团队属性自然，和实验场景相关，也表达独立开发者的判断力。其他备选见 [team_names.md](team_names.md)。

## 11 页方案 PPT 结构

1. 封面：上传图文 Word，交还已批注、可编辑的 Word。
2. 真实需求：聊天回答没有进入教师 Word 批改、归档和返还流程。
3. Agent 闭环：图文解析、证据判断、契约校验、教师终审、Word 原生回写。
4. 双案例：过敏原 ELISA 与 Unity 游戏开发的图文 Word 共用同一交付契约。
5. 产品体验：公网 Demo 的三分钟图文 Word 闭环。
6. 过敏原证据：标准曲线图片、正文证据与图片所在段落批注。
7. 游戏开发证据：合成运行截图与“运行成功不等于验证充分”。
8. 教师终审：保留原建议，把教师说明和最终成绩写回 Word。
9. 学情诊断：4 份复核样本、均分 73.5、最弱维度 53%。
10. 可复现工程：MiniMax-M3、GradeTrace、图片原段落定位、任意模板批改页、1 GiB、18 项测试。
11. 路线图与可编辑 Word/PPT/PDF/视频证据包。

## 初赛提交包

- 必交：作品简介；
- 必交：方案 PPT，另导出 PDF；
- 强烈建议：自然语音 Demo 视频和可操作公网原型；
- 建议附：公开仓库链接和本目录 README；
- 建议附：一页数据与合规说明；
- 建议附：当前完成/计划能力清单，避免把路线图写成既成事实。

## 当前最强叙事

不是“AI 替教师批改”，也不是在聊天框里生成另一段答案，而是“上传一份图文 Word，交还一份已经完成证据批注、成绩填写和教师评语回填的可编辑 Word”。现有项目已经有真实批改链路，参赛版把它从特定课程工具升级为可迁移、可复核、可诊断的高校实验教学 Agent。
