# 评测方案

## 评测目标

评测必须同时回答四个问题：能否跑通、评分是否接近教师、依据是否可追溯、是否在不确定时正确求助。

## 指标

| 维度 | 指标 | 初赛目标 | 复赛建议目标 |
|---|---|---:|---:|
| 闭环 | 端到端任务成功率 | 展示 1 条完整链路 | 至少 30 个匿名样本，成功率 >= 95% |
| 评分 | 与教师总分 MAE | 用样例说明 | <= 5 分 |
| 评分 | 5 分内一致率 | 用样例说明 | >= 80% |
| 维度 | 分项得分相关性 | 设计指标 | 每个维度报告，不只看总分 |
| 证据 | 有效证据覆盖率 | 展示引用 | >= 90% 的非零分维度有可定位证据 |
| 复核 | 高风险召回率 | 展示触发 | >= 90% 的证据缺失/冲突样本进入复核 |
| 效率 | 教师单份复核时间 | 记录基线 | 相比纯人工中位数下降 >= 50% |
| 稳定 | 同输入重复评分波动 | 固定低温度 | 总分标准差 <= 2 |
| 工程 | 从零部署成功率 | README 可执行 | 两个干净环境均可复现 |

目标值需要通过真实实验验证后才能写成结果，现阶段只作为验收门槛。

## 数据集设计

1. 公开模拟集：覆盖完整报告、缺数据、图表缺标注、结论矛盾、纯文本、图片不可读和接口失败。
2. Word 原生交付集：覆盖固定成绩表、无固定模板、正文批注、图片段落批注、教师终审后重新生成、原图片保留和 DOCX 可重新打开。
3. 教师金标集：经授权脱敏，由至少一位任课教师逐维度评分并标注关键证据。
4. 争议集：由两位教师独立评分，用于区分模型误差与教师间本身的不一致。

按课程划分训练/校准与测试数据，避免同一学生或同一模板跨集合泄漏。

## 对照

- 人工批改基线：教师原始耗时和评分；
- 无 Vision：只读文本；
- 无证据契约：只输出分数与理由；
- 无人工复核：所有模型结果直接通过；
- 完整系统：多模态证据 + 规则校验 + 教师复核。

消融结果可以证明每个 Agent 能力是否真正服务任务闭环。

## 失败注入

Demo 和测试应主动覆盖：

- LLM 或 Vision 超时；
- 文档损坏或格式不支持；
- rubric 缺项或分值不等于 100；
- 报告声明与表格/图片冲突；
- 学生信息缺失；
- 低置信度但模型仍给高分；
- 下载或注入失败。

系统应给出可理解状态、保留已完成证据并允许重试或人工接管。

## 运行证据

每次评测记录代码提交、模型/端点类别、配置摘要、rubric 版本、样本版本、耗时、Token/费用估算、异常和教师复核结果。公开报告只使用匿名聚合值。
